1. CORE PURPOSE & APPLICATION PROFILE
-------------------------------------------------------------------------------
VeroApp SMS Guard is an offline-first mobile security, anti-phishing, and telecom fraud
protection application. Its primary core functions are:
  1. Real-time interception and local AI classification of fraudulent SMS messages (smishing,
     bank verification theft, extortion).
  2. Telecom-layer automated rejection of confirmed nuisance, phishing, and scam phone calls
     using Android's official CallScreeningService.
  3. Real-time on-device scanning of suspicious URLs shared via messaging applications.

CRITICAL PRIVACY GUARANTEE:
All inference, pattern matching, contact verification, and database lookups occur
100% locally on the device processor and memory. Zero SMS texts, phone numbers, contacts,
or call logs are transmitted to external servers.

2. GOOGLE PLAY CONSOLE FORMULA DECLARATIONS (EXACT FORMULA FORMAT)
===============================================================================

A. RECEIVE_SMS
"Our app uses android.permission.RECEIVE_SMS to detect incoming SMS messages in real-time
because the app's primary core functionality is to classify fraudulent smishing and scam
messages before the user interacts with them. No data is collected or transmitted off the device."

B. READ_SMS
"Our app uses android.permission.READ_SMS to display the user's SMS messages within its
on-device Smart Inbox and categorize them into Clean and Spam/Suspicious folders because
it serves as a full-featured Default SMS Handler. No data is collected or transmitted off the device."

C. BROADCAST_SMS
"Our app uses android.permission.BROADCAST_SMS to receive SMS delivery intents as the
user-selected Default SMS application because Android platform architecture requires
this permission for SMS_DELIVER intents. No data is collected or transmitted off the device."

D. ROLE_SMS (DEFAULT SMS HANDLER)
"Our app uses ROLE_SMS to act as the primary SMS management application because intercepting
and isolating high-risk smishing messages before they trigger standard notification deception
requires default SMS handler status. No data is collected or transmitted off the device."

E. ROLE_CALL_SCREENING (android.telecom.CallScreeningService)
"Our app uses ROLE_CALL_SCREENING to evaluate incoming telephone numbers against a local
pre-packaged spam number database (126,000+ entries) because blocking fraudulent calls at the
telecom layer prevents predatory toll fraud. No data is collected or transmitted off the device."

F. READ_CALL_LOG
"Our app uses android.permission.READ_CALL_LOG as a backward-compatibility fallback for
devices running Android 9 (API 28) and below that lack CallScreeningService support to
identify recent spam callers. No data is collected or transmitted off the device."

G. READ_CONTACTS
"Our app uses android.permission.READ_CONTACTS to match incoming messages and calls against
the user's existing address book to display a verified 'Trusted Contact' green badge because
users need immediate visual confirmation that a message is from an acquaintance. No data is
collected or transmitted off the device."

H. POST_NOTIFICATIONS
"Our app uses android.permission.POST_NOTIFICATIONS to display urgent security warnings
when a high-risk smishing or phishing attempt is detected on-device because immediate user
alerting prevents accidental credential disclosure. No data is collected or transmitted off the device."

I. BIND_NOTIFICATION_LISTENER_SERVICE
"Our app uses BIND_NOTIFICATION_LISTENER_SERVICE to provide optional passive spam alerts for
users who prefer not to set VeroApp as their default SMS handler because this allows notification-based
threat warning without replacing their existing messaging app. No data is collected or transmitted off the device."

J. BIND_ACCESSIBILITY_SERVICE
"Our app uses BIND_ACCESSIBILITY_SERVICE to inspect URLs displayed on-screen in instant messaging
apps (e.g. WhatsApp, Telegram) in real-time because malicious phishing links delivered through chat
must be warned against before execution. A non-intrusive manual Share Target (Mode B) is also provided.
No data is collected or transmitted off the device."

K. INTERNET
"Our app uses android.permission.INTERNET exclusively for optional, user-initiated one-way downloads
of verified binary threat signature updates from public GitHub releases. No device identifiers,
telemetry, analytics, or user data are ever uploaded or transmitted."

3. REGULATORY COMPLIANCE QUESTIONS & ANSWERS
===============================================================================

Q1: What core feature requires the permission?
A1: Real-time on-device smishing detection (ROLE_SMS / RECEIVE_SMS), automated fraudulent
    call rejection (ROLE_CALL_SCREENING), and verified contact badging (READ_CONTACTS).

Q2: Why can't the feature work without it?
A2: Modern mobile operating systems restrict SMS interception and telecom-layer call rejection
    exclusively to apps holding the respective Default SMS and Call Screening roles. Without these
    permissions, an anti-fraud app cannot prevent the user from being exposed to fraudulent SMS
    payloads or predatory phone calls.

Q3: Is the permission used ONLY for that stated feature?
A3: YES. Permissions are strictly mapped 1:1 to their respective defensive functions. No cross-purpose
    utilization, data harvesting, or ad targeting is performed.

Q4: Is user data transmitted off-device?
A4: NO. VeroApp SMS Guard operates with a 100% Zero-Cloud Footprint. The application contains
    zero analytical SDKs, zero advertising networks, and transmits zero user bytes off the device.
